2. 移交前準備

不要只匯出 CSV。CSV 是教學紀錄報表，不含完整課表、例外、班級、段考目標、匯入批次與同步操作，不能取代 Google Sheet 複本。

3. 移交 GitHub 專案

推薦方式：轉移儲存庫擁有權

  1. 原擁有者開啟儲存庫 → Settings → General → Danger Zone → Transfer ownership。
  2. 輸入朋友的 GitHub 帳號與儲存庫名稱 teachflow，送出移轉。
  3. 朋友須在 1 天內接受移轉邀請；接受後到 Settings → Pages，確認 Source 為 GitHub Actions。
  4. 到 Settings → Secrets and variables → Actions → Variables，稍後建立新的兩個變數。
GitHub Pages 舊網址不會跟著儲存庫轉址。朋友必須使用新帳號下的 Pages 網址。若不想轉移原儲存庫，可由朋友建立新儲存庫再推送完整 Git 歷史；但 Issues、Actions 歷史、Stars 與舊網址不會自動搬遷。

轉移後必改

apps-script/Bridge.html 中的 PARENT_ORIGIN 必須改成朋友的新 GitHub Pages origin：

const PARENT_ORIGIN = "https://朋友的GitHub帳號.github.io";

此處只有 origin，不含 /teachflow/ 路徑，也不要有結尾斜線。

4. 搬遷完整 Google Sheet 資料

  1. 原擁有者打開目前試算表，先再次確認「TeachFlow資料」工作表存在且有資料。
  2. 將試算表分享給朋友為「編輯者」。
  3. 朋友用自己的帳號開啟後，選 檔案 → 建立副本，存到朋友自己的雲端硬碟。
  4. 開啟副本，從網址 /spreadsheets/d/這一段/edit 取得新 Sheet ID。
  5. 比對原檔與副本的工作表名稱、資料列數及最後一筆操作時間。
完成標準：朋友擁有副本，副本內「TeachFlow資料」列數與原檔一致，且最後一列 JSON 可正常顯示。

不要手動排序、刪欄、修改 JSON 或把「TeachFlow資料」改名。這是一份追加式操作紀錄，任意改動可能破壞跨裝置還原。

5. 在朋友帳號重建 Apps Script 後端

  1. 朋友到 script.google.com 建立新專案，名稱可用「TeachFlow Sync Bridge」。
  2. 把儲存庫 apps-script/Code.gs、Bridge.html、appsscript.json 的內容複製到新專案。
  3. 修改 Bridge.html 的 PARENT_ORIGIN 為朋友的新 GitHub Pages origin。
  4. 在 Apps Script 專案設定 → 指令碼屬性建立以下兩項。
屬性值是否可公開
GOOGLE_SHEETS_SPREADSHEET_ID步驟 4 取得的新 Sheet ID識別碼可出現在前端，但仍不要任意散布
TEACHFLOW_SYNC_SECRET重新產生至少 24 字元的隨機字串不可公開

部署 Web App

  1. 選 部署 → 新增部署作業 → 網頁應用程式。
  2. 執行身分選「我」；存取權限選「任何人」，並確認此選項允許未登入 Google 的訪客載入（官方設定值為 ANYONE_ANONYMOUS）。
  3. 完成 Google Drive、Docs、Sheets 權限授權。若 Drive OCR 回報服務未啟用，確認進階 Google 服務中的 Drive API v3 已啟用。
  4. 複製以 /exec 結尾的 Web App URL；不要使用測試用 /dev URL。
Web App 對外可載入，但真正的資料存取還有三層限制：GitHub Pages origin、同步存取碼與固定 Sheet ID。三者必須一致。

6. 更新 GitHub 設定並重新部署

在朋友擁有的儲存庫建立以下 GitHub Actions Variables：

變數名稱值
TEACHFLOW_SYNC_BRIDGE_URL朋友的新 Apps Script /exec URL
GOOGLE_SHEETS_SPREADSHEET_ID朋友的新 Sheet ID

接著提交 Bridge.html 的新 origin，推送到 main。GitHub Actions 會執行測試並部署 dist/。

npm test
npm run check
git add apps-script/Bridge.html
git commit -m "chore: transfer TeachFlow ownership"
git push

在 Actions 頁面確認 Deploy GitHub Pages 綠色完成，再開啟朋友的新正式網址。

7. 朋友的新裝置接手

  1. 用朋友的新 GitHub Pages 網址開啟 TeachFlow，必要時重新整理兩次，讓新版 Service Worker 接管。
  2. 按頂端「本機已儲存／尚未連線」狀態。
  3. 輸入新的 TEACHFLOW_SYNC_SECRET，按「連線並同步」。
  4. 連線成功後，可展開「自訂／變更同步存取碼」，輸入兩次新碼並儲存；新碼不會寫入 GitHub。
  5. 等待狀態變成「雲端已同步」。新裝置會從搬遷後的 Sheet 還原班級、課表、進度、段考目標與例外。
  6. 確認資料無誤後，才把網站加入主畫面。
若新裝置先產生示範資料，不要急著大量編輯。先完成雲端連線並核對遠端資料；若內容不一致，停止操作並執行下方回復方案。

8. 必做驗收表

9. 搬遷失敗的回復方案

  1. 不要刪除原 Sheet、原 Apps Script 或原 GitHub 儲存庫，至少保留到朋友完成全部驗收。
  2. 若新網站無法同步，先核對 GitHub Variables、Script Properties、Web App URL 與 PARENT_ORIGIN。
  3. 若新 Sheet 資料異常，停止在新網站編輯，重新從原 Sheet 建立一份乾淨副本，再更新兩邊 Sheet ID。
  4. 若 GitHub Pages 失敗，到 Actions 查看第一個紅色步驟；先在本機跑 npm test 與 npm run check。
  5. 回復期間仍可使用原網址與原 Sheet，但不要同時在新、舊兩套系統修改，否則操作紀錄會分叉。

10. 安全收尾

必做：撤銷先前曾貼在聊天中的 Google 服務帳戶私鑰。該金鑰不被目前 TeachFlow 前端使用，但既然曾公開出現，就應在 Google Cloud IAM 立即刪除並停用。不要把舊 JSON 憑證交給朋友。

移交完成定義

只有在朋友帳號擁有 GitHub 專案、Google Sheet 副本與 Apps Script 部署，且朋友的新網址能從新 Sheet 還原完整資料、成功新增同步操作後，才算完成移交。

本指南不包含任何密碼或私鑰，可直接交付。勾選狀態只存於開啟此檔案的瀏覽器 localStorage，不會上傳。
