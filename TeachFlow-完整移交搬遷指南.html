2. 移交前準備

不要只匯出 CSV。CSV 是教學紀錄報表，不含完整課表、例外、班級、段考目標、匯入批次與同步操作，不能取代 Google Sheet 複本。

3. 用 Fork 複製到朋友的 GitHub 帳號

Fork 會在朋友帳號建立一份可獨立修改的儲存庫，同時保留與原專案的 upstream 關係。原本的儲存庫與網站不受影響，也不需要轉移擁有權。

1建立 Fork

  1. 朋友先登入自己的 GitHub，開啟 te87037/teachflow。
  2. 按右上角 Fork。
  3. Owner 選朋友自己的帳號；Repository name 保持 teachflow。
  4. 勾選 Copy the default branch only 即可，然後按 Create fork。
  5. 完成後網址應是 https://github.com/朋友帳號/teachflow，頁面會標示「forked from te87037/teachflow」。
完成標準：朋友能在自己的 Fork 內看見 dist/、apps-script/、.github/workflows/pages.yml 與本移交 HTML。

2啟用 Fork 自己的 GitHub Actions

  1. 在朋友的 Fork 開啟 Actions。
  2. 若看到「Workflows aren’t being run」或確認提示，按 I understand my workflows, go ahead and enable them。
  3. 若仍無法執行，到 Settings → Actions → General，確認 Actions permissions 允許使用此專案引用的官方 Actions。
  4. 不要啟用「把 Secrets 傳回原始專案的 Pull Request」之類選項；TeachFlow 的正式部署只在朋友自己的 Fork 執行。

Fork 擁有自己的 Actions、設定與權限；原專案的 Variables／Secrets 不會自動複製過來。

3啟用朋友自己的 GitHub Pages

  1. 在朋友的 Fork 進入 Settings → Pages。
  2. 在 Build and deployment 的 Source 選 GitHub Actions。
  3. 朋友的正式網址會是 https://朋友帳號.github.io/teachflow/。
  4. 第一次部署要等本節其他設定完成後再執行；目前先記下這個網址與 origin。

4在 Fork 修改 PARENT_ORIGIN

apps-script/Bridge.html 中的 PARENT_ORIGIN 必須改成朋友的新 GitHub Pages origin：

const PARENT_ORIGIN = "https://朋友的GitHub帳號.github.io";

此處只有 origin，不含 /teachflow/ 路徑，也不要有結尾斜線。可直接在 GitHub 點檔案 → 鉛筆 Edit → 修改 → Commit changes，提交到朋友 Fork 的 main。

5建立朋友自己的 Actions Variables

完成 Google Sheet 與 Apps Script 後，到朋友的 Fork：

  1. 進入 Settings → Secrets and variables → Actions → Variables。
  2. 建立 TEACHFLOW_SYNC_BRIDGE_URL，值填朋友的新 Apps Script /exec 網址。
  3. 建立 GOOGLE_SHEETS_SPREADSHEET_ID，值填朋友的新 Sheet ID。
  4. 同步存取碼不要放在 GitHub Variable 或 Secret；它只存在 Apps Script 的 Script Properties。
Fork 是獨立部署：朋友之後可自由修改自己的 Fork。若要取得你後續的更新，可在 Fork 首頁按 Sync fork → Update branch；同步前應先查看差異，避免覆蓋朋友自己的 PARENT_ORIGIN 或部署設定。

4. 搬遷完整 Google Sheet 資料

  1. 原擁有者打開目前試算表，先再次確認「TeachFlow資料」工作表存在且有資料。
  2. 將試算表分享給朋友為「編輯者」。
  3. 朋友用自己的帳號開啟後，選 檔案 → 建立副本，存到朋友自己的雲端硬碟。
  4. 開啟副本，從網址 /spreadsheets/d/這一段/edit 取得新 Sheet ID。
  5. 比對原檔與副本的工作表名稱、資料列數及最後一筆操作時間。
完成標準：朋友擁有副本，副本內「TeachFlow資料」列數與原檔一致，且最後一列 JSON 可正常顯示。

不要手動排序、刪欄、修改 JSON 或把「TeachFlow資料」改名。這是一份追加式操作紀錄，任意改動可能破壞跨裝置還原。

5. Apps Script 從零建立與部署（初學者版）

這一節不需要會寫程式。照順序完成 ① 建立專案、② 放入三個檔案、③ 設定兩個屬性、④ 部署、⑤ 驗證即可。請全程使用朋友自己的 Google 帳號。

先準備兩個值：朋友的新 Google Sheet ID，以及朋友的新 GitHub Pages origin（例如 https://friend.github.io）。不要把同步存取碼貼進 GitHub 或這份 HTML。

1建立空白 Apps Script 專案

  1. 登入朋友的 Google 帳號，開啟 script.google.com/home。
  2. 按左上方 「新增專案」。若畫面先顯示 Apps Script 首頁，按 「新增指令碼」或左上角的加號。
  3. 點頂端「未命名的專案」，改名為 TeachFlow Sync Bridge。
  4. 畫面左側應看到預設檔案 Code.gs。
完成畫面：專案名稱是 TeachFlow Sync Bridge，左側有 Code.gs。

2放入 Code.gs

  1. 另開分頁，開啟 GitHub 的 apps-script/Code.gs。
  2. 按 GitHub 程式碼右上方的複製按鈕；若找不到，按 Raw 後按 Ctrl + A、Ctrl + C。
  3. 回到 Apps Script，點左側 Code.gs，在編輯區按 Ctrl + A 刪掉預設內容，再貼上完整程式碼。
  4. 按 Ctrl + S，或按上方磁碟片圖示儲存。

不要只複製畫面看得到的前幾行；必須從第一行到最後一個 } 全部複製。

3建立 Bridge.html 並修改允許網址

  1. 在 Apps Script 左側「檔案」旁按 ＋ → 選 HTML。
  2. 檔名輸入 Bridge（不要輸入副檔名）；建立後左側會顯示 Bridge.html。
  3. 開啟 GitHub 的 apps-script/Bridge.html，複製全部內容，覆蓋 Apps Script 內的預設 HTML。
  4. 找到 const PARENT_ORIGIN = "https://te87037.github.io";，只把引號內改成朋友的新 Pages origin。
const PARENT_ORIGIN = "https://朋友帳號.github.io";
  • 正確：https://friend.github.io
  • 錯誤：https://friend.github.io/teachflow/（多了路徑）
  • 錯誤：https://friend.github.io/（多了結尾斜線）

修改完成後按 Ctrl + S。

4顯示並替換 appsscript.json

  1. 按左側齒輪 專案設定。
  2. 勾選 「在編輯器中顯示『appsscript.json』資訊清單檔案」。
  3. 回到左側 編輯器 <>，點新出現的 appsscript.json。
  4. 開啟 GitHub 的 apps-script/appsscript.json，複製全部內容並覆蓋原內容，再儲存。
這一步會完成：時區設為 Asia/Taipei、使用 V8、加入 Sheets／Drive／Docs 權限，並啟用 Drive API v3 供圖片 OCR 使用。若專案使用 Apps Script 預設 Cloud 專案，Google 官方說加入進階服務後會自動啟用對應 API。

5建立兩個 Script Properties

  1. 按左側齒輪 專案設定，向下捲到 指令碼屬性（Script Properties）。
  2. 第一次設定按 新增指令碼屬性；之後要修改則按 編輯指令碼屬性。
  3. 逐字建立下表兩列。名稱區分大小寫，不可多空格。
  4. 按 儲存指令碼屬性。
屬性名稱（左欄）值（右欄）注意
GOOGLE_SHEETS_SPREADSHEET_ID步驟 4 取得的新 Sheet ID只貼 ID，不要貼完整網址
TEACHFLOW_SYNC_SECRET自行決定的初始同步存取碼建議至少 12 字元且不可公開；接手後可在 TeachFlow 網站內再自訂

Sheet ID 是試算表網址中 /d/ 與 /edit 之間的英數字串。

6建立第一次正式 Web App 部署

  1. 先確認三個檔案都已儲存：Code.gs、Bridge.html、appsscript.json。
  2. 按右上角 部署 → 新增部署作業。
  3. 「選取類型」旁按齒輪 → 選 網頁應用程式（Web app）。
  4. 說明可填 TeachFlow first deployment。
  5. 「執行身分」選 我（部署者／USER_DEPLOYING）。
  6. 「誰可以存取」選 任何人，必須允許未登入 Google 的瀏覽器載入（官方設定值 ANYONE_ANONYMOUS）。
  7. 按 部署。第一次會要求授權：按「授予存取權」或「審查權限」→ 選朋友帳號 → 檢查要求的 Sheets、Drive、Docs 權限 → 按「允許」。
  8. 若顯示「Google 尚未驗證這個應用程式」，只有在確認這是朋友自己剛建立、且程式碼來自此 TeachFlow 儲存庫時，才展開進階選項繼續；若專案名稱或帳號不符就停止。
  9. 部署完成後，複製 網頁應用程式網址，它必須以 /exec 結尾。
不要使用 /dev：「測試部署作業」產生的 /dev 網址只有專案編輯者可用。GitHub Variables 必須保存正式的 /exec 網址。

7以後修改程式時，更新原部署

只按「儲存」不會更新正式網站使用的版本。每次修改 Apps Script 後都要完成以下流程：

  1. 按 部署 → 管理部署作業。
  2. 在左側選目前使用中的 Web App 部署，按右上方鉛筆 編輯。
  3. 「版本」下拉選單選 新版本，說明填本次修改內容。
  4. 按 部署。更新原部署會保留同一個 /exec 網址，不必再改 GitHub Variable。
判斷是否更新成功：管理部署作業顯示新的版本號與剛才的更新時間。

8先做後端基本驗證

  1. 把剛取得的 /exec 網址貼到新的無痕視窗。
  2. 正常時會出現很簡單的空白頁；頁面標題可能是 TeachFlow Sync Bridge。這代表 Web App 可公開載入。
  3. 若要求登入 Google，代表「誰可以存取」不是任何人；回到「管理部署作業」修正。
  4. 完成下一節 GitHub Variables 後，再由 TeachFlow 網站輸入同步存取碼做完整驗證。

Apps Script 常見錯誤對照

看到的狀況原因怎麼修
BACKEND_NOT_CONFIGURED兩個 Script Properties 缺少一個或名稱打錯到專案設定逐字核對名稱和值，再儲存
INVALID_SYNC_SECRET網站輸入的碼與 Script Property 不同先用目前有效碼連線；之後可在網站內自訂新碼
SPREADSHEET_NOT_ALLOWEDApps Script 與 GitHub Variable 使用不同 Sheet ID讓兩邊的 GOOGLE_SHEETS_SPREADSHEET_ID 完全一致
Drive is not defined／OCR 失敗Drive API v3 沒有啟用或資訊清單未替換核對 appsscript.json 的 enabledAdvancedServices，儲存後部署新版本
修改後仍是舊功能只儲存程式，沒有更新版本化部署部署 → 管理部署作業 → 編輯 → 新版本 → 部署
Bridge 載入逾時PARENT_ORIGIN 錯誤，或 Web App 不允許匿名存取origin 只留協定與網域；確認「誰可以存取」為任何人
找不到「任何人」選項學校／公司 Workspace 管理政策禁止匿名 Web App改用允許此設定的個人 Gmail，或請網域管理員開放；不要改成要求每台裝置登入
/dev 可以、/exec 不行測試程式尚未建立或更新正式版本建立正式部署，或把既有部署切到新版本
Web App 對外可載入，但真正的資料存取還有三層限制：GitHub Pages origin、同步存取碼與固定 Sheet ID。三者必須一致。

7. 朋友的新裝置接手

  1. 用朋友的新 GitHub Pages 網址開啟 TeachFlow，必要時重新整理兩次，讓新版 Service Worker 接管。
  2. 按頂端「本機已儲存／尚未連線」狀態。
  3. 輸入新的 TEACHFLOW_SYNC_SECRET，按「連線並同步」。
  4. 連線成功後，可展開「自訂／變更同步存取碼」，輸入兩次新碼並儲存；新碼不會寫入 GitHub。
  5. 等待狀態變成「雲端已同步」。新裝置會從搬遷後的 Sheet 還原班級、課表、進度、段考目標與例外。
  6. 確認資料無誤後，才把網站加入主畫面。
若新裝置先產生示範資料，不要急著大量編輯。先完成雲端連線並核對遠端資料；若內容不一致，停止操作並執行下方回復方案。

8. 必做驗收表

9. 搬遷失敗的回復方案

  1. 不要刪除原 Sheet、原 Apps Script 或原 GitHub 儲存庫，至少保留到朋友完成全部驗收。
  2. 若新網站無法同步，先核對 GitHub Variables、Script Properties、Web App URL 與 PARENT_ORIGIN。
  3. 若新 Sheet 資料異常，停止在新網站編輯，重新從原 Sheet 建立一份乾淨副本，再更新兩邊 Sheet ID。
  4. 若 GitHub Pages 失敗，到 Actions 查看第一個紅色步驟；先在本機跑 npm test 與 npm run check。
  5. 回復期間仍可使用原網址與原 Sheet，但不要同時在新、舊兩套系統修改，否則操作紀錄會分叉。

10. 安全收尾

必做：撤銷先前曾貼在聊天中的 Google 服務帳戶私鑰。該金鑰不被目前 TeachFlow 前端使用，但既然曾公開出現，就應在 Google Cloud IAM 立即刪除並停用。不要把舊 JSON 憑證交給朋友。

移交完成定義

只有在朋友帳號擁有 GitHub 專案、Google Sheet 副本與 Apps Script 部署，且朋友的新網址能從新 Sheet 還原完整資料、成功新增同步操作後，才算完成移交。

本指南不包含任何密碼或私鑰，可直接交付。勾選狀態只存於開啟此檔案的瀏覽器 localStorage，不會上傳。
